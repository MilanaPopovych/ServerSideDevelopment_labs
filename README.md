# Технології розроблення серверних компонентів. Лабораторна робота №1

Базовий веб-застосунок із системними ендпоінтами перевірки стану (Liveness/Readiness), контейнеризацією через Docker Compose та CI-пайплайном у GitHub Actions.

## Структура проєкту
- `app/app.py`: Flask-застосунок із ендпоінтами `/healthz/live` та `/healthz/ready`.
- `app/__init__.py`: порожній файл для позначення модуля Python.
- `Dockerfile`: інструкція збірки образу застосунку.
- `docker-compose.yaml`: конфігурація локального запуску сервісу.
- `requirements.txt`: зафіксовані залежності Python.
- `.github/workflows/ci.yml`: конфігурація CI (лінтер Ruff, збірка образу, валідація Compose).

## Підготовка до запуску
Перед запуском проєкту виконайте перевірки:
1. Встановленої версії Git: `git --version`
2. Версії Docker Engine з підтримкою Docker Compose v2: `docker --version`, `docker compose version`
3. Версії Python: `py --version` (або `python --version`)

## Інструкція з локального запуску через Docker Compose

### 1. Клонування репозиторію
В терміналі виконайте копіювання репозиторію на комп'ютер та перейдіть до кореневої директорії застосунку:

```bash
git clone https://github.com/your-username/ServerSideDevelopment_labs.git
cd ServerSideDevelopment_labs
```

### 2. Запуск та перевірка статусу контейнера
Створіть та запустіть контейнер з попередньою збіркою образів (--build) у фоновому режимі (-d): 

```bash
docker compose up --build -d
```
Для перевірки статусу контейнера, виконайте команду з виведення списку контейнерів:

```bash
docker ps
```

### 3. Перевірка роботи сервісу (Healthcheck API)

Перевірка роботи системних проб можлива або за допомогою інструменту командного рядка `curl`, або безпосередньо в браузері за адресою локального хоста.
   - Перевірка в терміналі: 
   ```bash
   curl -i http://localhost:8080/healthz/live
   curl -i http://localhost:8080/healthz/ready
   ```
   Очікувана відповідь для обох запитів повинна містити заголовок `HTTP/1.1 200 OK` та відповідне JSON-тіло.
   
   - Перевірка в браузері: \
   В адресний рядок обраного браузера введіть в окремих вкладках адреси "http://localhost:8080/healthz/live", "http://localhost:8080/healthz/ready" \
   Щоб переглянути HTTP Status Code (`200 OK`), відкрийте панель розробника **DevTools** (`F12` або `Ctrl+Shift+I`), перейдіть на вкладку **Network** та оновіть сторінку (`F5`).

### 4. Перегляд логів застосунку
Для перегляду логів виконання в режимі реального часу виконайте:

```bash
docker compose logs -f
```

В разі коректної роботи застосунку в Docker-контейнері та успішної обробки запитів у журналі мають бути присутні наступні повідомлення:
`"GET /healthz/live HTTP/1.1" 200 -` \
`"GET /healthz/ready HTTP/1.1" 200 -` 

*(Для виходу з режиму перегляду логів натисніть `Ctrl+C`).*

### 5. Зупинка контейнера
Для зупинки сервісу та видалення контейнерів, попередньо створених за допомогою `up`, виконайте:

```bash
docker compose down
```

## Безперервна інтеграція (Continuous Integration)
У проєкті налаштовано конвеєр безперервної інтеграції (CI pipeline) за допомогою GitHub Actions (.github/workflows/ci.yml). При кожному `push` або `pull_request` у головну гілку (`main`) автоматично виконуються такі етапи:
1. Перевірка якості та стилю коду за допомогою лінтера Ruff.
2. Автоматична збірка Docker-образу `expense-app:latest`.
3. Перевірка синтаксису файла конфігурації `docker-compose.yaml`.
